# Critical Reading · 批判性精读

一个用于 Codex 的阅读与研究 Skill：结合历史经验、跨领域研究、第一性原理和多 agent 评审，区分材料中的已有知识与真实贡献，建立清晰的分层知识模型。

> 这份材料相对于人类已有的知识，究竟增加了什么？证据是什么？在什么条件下成立？

## 适合用来做什么

- **论文精读**：拆解研究问题、已有基线、方法、证据与适用边界。
- **创新性分析**：区分已有方法、组合或迁移、新证据、新方法和新理论。
- **书籍章节学习**：梳理前置概念，提炼核心机制和知识之间的依赖关系。
- **研究讨论**：引入不同分析立场，寻找反例、替代解释和待验证的问题。
- **教学准备**：把阅读结论组织成适合讲授的结构。

普通翻译、简单摘要和局部解释通常不需要完整协作流程。

## 工作方式

### 1. 建立阅读骨架

围绕“问题 → 已有方法 → 核心主张 → 证据 → 适用边界”整理原文，明确哪些内容已知，哪些内容需要核实。

### 2. 回看历史，连接其他领域

追溯前驱工作、类似问题与历史成败经验，寻找其他领域可迁移的机制。优先关注影响深远且证据扎实的成果，同时考虑近期工作和反例，不把引用量当作正确性的证明。

### 3. 从第一性原理拆解

检查定义、假设、约束和推导关系：结论为什么成立？哪些条件不可缺少？去掉某个假设后，结论会怎样变化？

### 4. 提炼最小知识增量

用尽可能少的命题说明材料相对已有基线增加了什么，同时保留关键证据、不确定性和适用条件。已有组件的新组合也可能是重要贡献。

### 5. 多视角评审与收敛

在环境支持且存在独立任务时，启动实际子 agent，先独立评估，再围绕具体分歧交叉质疑，最后由主 agent 核验和整合。

## 多 personality agent

这里的 personality 是角色的分析立场、关注点和工作风格。各角色围绕共同材料承担不同任务。

| 角色 | 关注什么 |
| --- | --- |
| 历史学者 | 前驱工作、历史来源、已有基线和原创性 |
| 第一性原理分析者 | 基本假设、机制、推导与失效条件 |
| 严格审稿人 | 证据缺口、替代解释、反例与过度宣称 |
| 跨领域研究者 | 其他领域的相关成果、可迁移机制及边界 |
| 教学者 | 前置概念、最小知识增量与分层知识结构 |

默认优先选择历史学者、第一性原理分析者和严格审稿人，根据任务替换或补充其他角色。主 agent 负责分配任务、核实证据、组织质疑及汇总结果。

协作顺序：

```text
共同原文与用户目标
        ↓
各角色独立评审
        ↓
主 agent 整理关键分歧
        ↓
一轮交叉质疑
        ↓
必要时再做一轮定向核实
        ↓
形成结论，保留尚未解决的分歧
```

并发数量取决于运行环境；名额不足时分批执行。无法使用子 agent 时，会明确改用单 agent 多视角分析，不声称已完成独立 agent 评审。多个角色意见一致也不能代替证据。

## 安装到 Codex

这是一个指令型 Skill，无需安装 Python 或 npm 依赖。将技能文件放入 Codex 用户级技能目录，即可跨项目使用。

### 手动安装

1. 下载本仓库并解压。
2. 在用户级技能目录中创建 `critical-reading` 文件夹。
3. 将本仓库的 `SKILL.md` 和整个 `agents` 文件夹复制进去。

默认安装结构：

```text
~/.codex/skills/critical-reading/
├── SKILL.md
└── agents/
    └── openai.yaml
```

Windows 中，`~` 对应你的用户目录，例如 `C:\Users\你的用户名`。如果设置了 `CODEX_HOME`，请安装到该目录下的 `skills/critical-reading`。

### 使用 Git 安装

如果目标文件夹尚不存在，可以直接克隆。

**Windows PowerShell：**

```powershell
$skillBase = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $env:USERPROFILE '.codex' }
$skillTarget = Join-Path $skillBase 'skills/critical-reading'
git clone https://github.com/pixxielf/critical-reading-skills--.git "$skillTarget"
```

**macOS / Linux：**

```bash
git clone https://github.com/pixxielf/critical-reading-skills--.git "${CODEX_HOME:-$HOME/.codex}/skills/critical-reading"
```

安装后，在新会话中调用。若没有识别到技能，重启 Codex 后再试。已有手动安装版本时，可更新技能文件；不要向已有目录重复执行 `git clone`。

## 使用示例

在 Codex 中提供原文、可访问的链接或本地文件，并使用 `$critical-reading` 调用。

### 精读论文

```text
请用 $critical-reading 精读这篇论文。
区分已有知识和真正新增的贡献，核实相关工作，给出关键证据及适用边界。
```

### 多 agent 评审

```text
请用 $critical-reading 分析这篇论文。
在环境支持时，启动历史学者、第一性原理分析者和严格审稿人三个子 agent，
先独立评审，再交叉质疑，最后汇总共识、分歧和需要进一步验证的问题。
```

### 阅读书籍章节

```text
请用 $critical-reading 帮我理解这一章。
我已经掌握基础概念，请重点解释新增知识、关键假设以及它与前面章节的关系。
```

### 准备教学内容

```text
请用 $critical-reading 分析这份材料，并加入教学者和跨领域研究者视角。
面向有基础但不了解该主题的学生，组织一份讲授提纲，保留关键证据和来源。
```

## 会得到什么

默认输出紧凑的中文分析，长度随任务调整：

1. **核心结论**：材料解决了什么，最有价值的新增知识是什么。
2. **已知与新增**：对应主张、已有基线、真实增量、证据和边界。
3. **知识模型**：从基础概念到机制、方法、结果和应用的分层结构。
4. **历史与跨领域联系**：能够帮助理解或决策的相关案例。
5. **批判性判断**：最强贡献、关键缺口、未决分歧和后续验证方向。

输出不预设固定压缩比例，也不要求所有角色达成一致。

## 能力边界

- 全文不可用时，会明确阅读范围，不把摘要分析当作全文精读。
- 检索和子 agent 能力由宿主环境提供，安装本 Skill 不会自动开启这些工具。
- 无法检索相关工作时，原创性判断只能是暂定结论。
- 结论应区分原文陈述、外部已验证知识与分析推断；重要判断仍需核对来源。
- 多 agent 协作可能增加耗时和用量，其效果取决于材料、模型与工具；本仓库不提供准确率提升的量化保证。
